Future Work Worth Pursuing for HBase 2.x in the Community

September 6, 2019 · Zheng Hu

HBase 2.0.0 shipped on April 30, 2018—about 15 months ago as of this writing. HBase 2.0.x is EOL with no further releases. HBase 2.1 is at 2.1.6 and likely will not be maintained much longer. Stable 2.x lines will be 2.2.x and 2.3.x, especially 2.2.x as the version battle-tested at large shops.

Work I think deserves focus on HBase 2.x:

  1. Procedure V2 and Assignment V2 give distributed workflows atomicity through a framework—a pain point in 1.x. Example: create table steps—(a) add a ZK znode, (b) create table directory on the filesystem, (c) generate assign tasks and open regions on RegionServers. In 1.x any step failing could leave inconsistent state requiring HBCK. 2.x addresses this with the framework, but rewriting flows in Procedure V2 introduces bugs; stabilizing this is top priority.

  2. HBCK2 should cover more failure modes. Procedure V2 lowers inconsistency risk, but bugs remain. HBCK2 today mainly fixes assign/unassign issues; region overlap and holes should be supported too so operators have tools when things go wrong.

  3. In-Memory Compaction is a large win—in our 10-billion-row tests, write p999 stayed under ~50ms with stable latency. The community has not made it the default memstore (DefaultMemstore on ConcurrentSkipListMap still has worse latency control). We hit hard-to-debug issues such as HBASE-22608. Making the feature production-solid is high priority.

  4. MOB is valuable—one API for any cell size with normal atomic semantics. Downsides remain: large-value MOB compaction runs on the Master—a huge, slow single point given network and CPU limits. Sharding compaction to RegionServers is needed but not done yet.

  5. Off-heap on read/write paths can surface byte-corruption bugs that reproduce only under specific conditions, plus potential leaks once memory is manual. This area needs attention.

  6. Aside from flush and snapshot, management flows are Procedure V2–ized. Migrating flush and snapshot to Procedure V2 removes redundant Procedure V1 code and lets V1 be deleted.

  7. Replication still uses ZK; with serial replication each region holds a znode—stress on ZK at scale. Moving replication state to Meta is necessary. I started this work but hit Master/RegionServer deadlock on startup, likely requiring Master startup changes. Higher-priority work intervened; long term, Meta-backed replication is required.

  8. CCSMap (Alibaba’s compressed ConcurrentSkipListMap) is GC-friendly on the write path. Community merge to master lacks bandwidth; the goal is a pluggable component—or standalone dependency—to replace JDK ConcurrentSkipListMap, usable beyond HBase.

  9. Tiered block cache: L1 index/data blocks, L2 off-heap BucketCache, L3 SSD BucketCache—trim HDFS protocol overhead, improve locality, and boost read performance.
